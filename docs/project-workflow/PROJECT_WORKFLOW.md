## 1. 项目愿景与需求分析

### 1.1 核心痛点

- 传统记账App需要手动选择分类，步骤繁琐
- 用户记账意愿低，坚持记账难
- 分类体系固定，不能适应个人消费习惯

### 1.2 解决方案

- **自然语言输入**: 用户只需描述消费内容
- **AI智能分类**: 自动识别消费类别
- **自适应分类**: 根据用户习惯动态创建/调整分类

### 1.3 核心功能清单

#### MVP功能 (Phase 1)

| 功能         | 优先级 | 描述                           |
| ------------ | ------ | ------------------------------ |
| 智能记账输入 | P0     | 输入描述，AI自动解析金额、分类 |
| 自动分类     | P0     | 基于NLP/LLM的智能分类引擎      |
| 分类管理     | P0     | 查看/编辑/创建/删除分类        |
| 账单列表     | P0     | 按时间、分类查看消费记录       |
| 消费统计     | P1     | 图表展示消费趋势               |
| 预算管理     | P1     | 设置月度预算，超支提醒         |

#### AI Agent功能 (Phase 2-3)

| 功能         | 优先级 | 描述                                    |
| ------------ | ------ | --------------------------------------- |
| AI智能检索   | P0     | 自然语言查询历史账单，如"我上周剪过头发吗？" |
| AI消费洞察   | P1     | 异常检测、趋势分析、主动推送洞察         |
| AI智能建议   | P1     | 基于消费数据的个性化省钱建议             |
| AI对话助手   | P1     | 多轮对话、上下文记忆、自然语言交互       |

#### 扩展功能 (Phase 4+)

| 功能         | 优先级 | 描述                           |
| ------------ | ------ | ------------------------------ |
| 数据导出     | P2     | 导出CSV/Excel                  |
| 多账户支持   | P2     | 现金、银行卡、支付宝等         |
| 语音输入     | P2     | 语音记账，转文字后AI解析       |
| 图片识别     | P2     | 拍照识别小票自动记账           |

### 1.4 AI分类示例

```
输入: "中午和同事吃了顿火锅，花了158"
输出: { amount: 158, category: "餐饮", subcategory: "火锅", description: "中午和同事吃了顿火锅" }

输入: "打车去公司23.5"
输出: { amount: 23.5, category: "交通", subcategory: "打车", description: "打车去公司" }

输入: "交了这个月房租3500"
输出: { amount: 3500, category: "住房", subcategory: "房租", description: "交了这个月房租" }
```

## 3. 技术选型

### 3.1 前端方案对比


| 方案             | 优点                         | 缺点                   | 推荐度     |
| ---------------- | ---------------------------- | ---------------------- | ---------- |
| **Flutter**      | 一套代码双端，性能好，UI一致 | 学习曲线Dart语言       | ⭐⭐⭐⭐⭐ |
| **React Native** | JS生态丰富，社区大           | 性能略逊，双端不一致   | ⭐⭐⭐⭐   |
| **原生开发**     | 性能最优，API访问完整        | 开发成本高，需维护两套 | ⭐⭐⭐     |

**推荐: Flutter** - 适合个人/小团队快速开发，UI一致性强

### 3.2 后端方案对比


| 方案         | 优点                         | 缺点                       | 推荐度   |
| ------------ | ---------------------------- | -------------------------- | -------- |
| **Firebase** | 快速搭建，免运维，实时同步   | 国内访问问题，成本随量增长 | ⭐⭐⭐⭐ |
| **Supabase** | 开源Firebase替代，PostgreSQL | 相对较新                   | ⭐⭐⭐⭐ |
| **自建后端** | 完全可控，无vendor lock-in   | 开发运维成本高             | ⭐⭐⭐   |

**推荐: Supabase/自建** - 考虑到国内访问和数据隐私

### 3.3 AI方案对比


| 方案                                     | 优点             | 缺点             | 推荐度     |
| ---------------------------------------- | ---------------- | ---------------- | ---------- |
| **调用LLM API** (OpenAI/Claude/通义千问) | 效果好，开发快   | 有网络/成本依赖  | ⭐⭐⭐⭐⭐ |
| **本地小模型** (BERT/DistilBERT)         | 离线可用，隐私好 | 效果有限，需训练 | ⭐⭐⭐     |
| **规则+NLP混合**                         | 轻量，可控       | 覆盖面窄         | ⭐⭐⭐     |

**推荐: LLM API + 规则兜底**

- 主力: 调用大模型API (通义千问/文心一言 国内友好)
- 兜底: 关键词匹配规则 (离线/网络异常时)
- 进阶: 收集用户数据后微调本地模型

### 3.4 推荐技术栈

                      │

### 5.2 数据库设计

```sql
-- 用户表
CREATE TABLE users (
    id UUID PRIMARY KEY,
    email VARCHAR(255) UNIQUE,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 分类表
CREATE TABLE categories (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    name VARCHAR(50) NOT NULL,          -- 如: "餐饮"
    icon VARCHAR(10),                    -- 如: "🍜"
    parent_id UUID REFERENCES categories(id),  -- 支持子分类
    is_system BOOLEAN DEFAULT FALSE,     -- 系统预设 vs 用户自建
    created_at TIMESTAMP DEFAULT NOW()
);

-- 交易记录表
CREATE TABLE transactions (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    amount DECIMAL(10,2) NOT NULL,
    description TEXT,                    -- 用户原始输入
    category_id UUID REFERENCES categories(id),
    transaction_date DATE NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    ai_confidence FLOAT,                 -- AI分类置信度
    user_confirmed BOOLEAN DEFAULT FALSE -- 用户是否确认
);

-- AI学习记录表 (用于后续微调)
CREATE TABLE ai_training_data (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    input_text TEXT NOT NULL,
    predicted_category_id UUID,
    actual_category_id UUID,            -- 用户修正后的分类
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 5.3 AI分类引擎设计

```
用户输入: "中午和同事吃了顿火锅158元"
              │
              ▼
    ┌─────────────────┐
    │   预处理模块      │  → 清洗文本、提取数字
    └────────┬────────┘
              │
              ▼
    ┌─────────────────┐
    │  规则引擎 (快速)  │  → 关键词匹配已知模式
    │  "火锅" → 餐饮   │     (离线可用)
    └────────┬────────┘
              │
         命中? ├─ 是 → 返回结果 (置信度: 0.9)
              │
         否   ▼
    ┌─────────────────┐
    │  LLM API 调用    │  → 发送给大模型分析
    │  (通义千问/GPT)  │     Prompt: "将以下消费描述分类..."
    └────────┬────────┘
              │
              ▼
    ┌─────────────────┐
    │  结果解析 & 校验  │  → 解析JSON、校验格式
    └────────┬────────┘
              │
              ▼
    ┌─────────────────┐
    │  用户确认卡片    │  → 展示结果，用户可修改
    └─────────────────┘
```

**Prompt 设计示例**:

```
你是一个记账助手。请分析以下消费描述，提取信息并分类。

可用分类: 餐饮, 交通, 购物, 住房, 娱乐, 教育, 医疗, 社交, 其他

用户输入: "{input}"

请返回JSON格式:
{
  "amount": 数字,
  "category": "分类名",
  "subcategory": "子分类(可选)",
  "description": "精简描述",
  "confidence": 0-1的置信度
}
```
